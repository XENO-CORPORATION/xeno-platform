01 / design

Lay out real screens with auto-layout

Auto-layout works like flexbox on the canvas: direction, gap, per-side padding, hug, fill and wrap, with nested frames reflowing as content changes. Style it with tokens, fill stacks, gradients, shadows, blurs and masks.

Shift+A Try it in the demo →
02 / systematize

Build it once as a component

Components carry variants and properties. Instances keep their overrides when the main component changes, and you can swap or detach them. Publish a library and subscribe to it from other files.

Ctrl+Alt+K Try it in the demo →
03 / collaborate

Work in the same file

Cursors, selections and presence sync live, and undo only reverts your own edits. Today this runs across windows on one machine. Networked sessions arrive with the xeno-comms server.

C · comment Try it in the demo →
04 / prototype

Click through it before anyone builds it

Wire frames into flows with click, hover, drag and delay triggers. Smart-animate between frames, add overlays, scroll behaviour and device shells, then present.

Present ▶ Try it in the demo →
05 / hand off

Give developers code that compiles

Inspect any node for CSS or Tailwind. The output is token-aware, so colors and spacing arrive as your variables, not as loose hex values.

Copy as Tailwind Try it in the demo →
06 / trust it

Built not to lose work

Every action is undoable. Files autosave with crash recovery, and every release passes its test suite and an end-to-end run against the packaged build.

Autosave + crash recovery Try it in the demo →
Agent panel

An agent that edits through the same API as you.

The agent’s tools are the plugin document API, so every change it makes is a real node you can select, and one undo away. It can also audit a design and review it visually.

Inside XENO

Part of the XENO ecosystem, not a silo.

Canvas owns live, multi-author product design. Raster and print vector stay in Pixel, motion in Motion, and 3D in xeno-3d. Shared services handle vectors, sync, inference and accounts.
