- **`corpus.corpus.query`** — The verified truth of a workspace, division or project: its tenets (a claim and the assay that would disprove it) with the latest signed verdict, the doctrine it inherits from wider scopes (binding here), and narrower scopes’ tenets by reference. Read this before asserting a fact about the scope; an empty answer is an answer. Optional q filters by key, subject or claim.
  - arguments: `scope`* string, `id`* string, `q` string
  - reply: `corpus` — id, scope, scopeId, subject, workspaceId.; `tenets` — Own live tenets: key, kind, subject, claim, assay, expect, cadence, latest (signed verdict or null), freshness.; `inheritedDoctrine` — Doctrine from wider scopes, binding here (from = where it lives).; `aggregated` — Narrower scopes’ tenets BY REFERENCE: id, key, subject, from, state, freshness.
- **`corpus.corpus.assess`** — Which tenets of a scope hold, lapsed, errored, are aging past their cadence, or were never assayed. Writes nothing. Use it to decide what to re-assay or what to propose.
  - arguments: `scope`* string, `id`* string
  - reply: `corpus` — object; `summary` — tenets, held, lapsed, error, never, aging.; `tenets` — id, key, from, state, freshness (fresh|due|warn|expired|never), stale.
- **`corpus.proposal.create`** — Suggest adding, superseding or retiring a tenet. It is NOT applied: a person who administers the scope reads it and ratifies or rejects it in the Corpus tab. A tenet must carry its assay {kind, run} and expect; doctrine (kind "doctrine") carries none. A wider scope may not assert about a narrower scope’s subject.
  - arguments: `scope`* string, `id`* string, `action` string, `tenet` object, `target_tenet_id` string, `rationale`* string
  - reply: `proposal` — id, action, tenet, rationale, state ("proposed" until a person ratifies or rejects it).; `note` — string
