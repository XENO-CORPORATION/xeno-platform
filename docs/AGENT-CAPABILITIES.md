- **`canvas.canvas.list`** — The canvases you can see: yours, and those on projects you are on. With `project`, only that project’s.
  - arguments: `project` string
  - reply: `canvases` — id, name, project, updatedAt of each canvas you can see.
- **`canvas.canvas.get`** — A canvas: every item (task cards with their live title and status, notes, links, groups) with its position, and the connections between items.
  - arguments: `canvas`* string
  - reply: `canvas` — id, name, revision, project, url, items[] (id, type, x, y, width, height and what it shows), connections[] (id, from, to, link?, label?).
- **`canvas.canvas.create`** — Start a canvas. With `project`, everyone on the project sees it (you must be able to edit the project); without, it is yours alone.
  - arguments: `name`* string, `project` string
  - reply: `canvas` — id, name, revision, project, url, items[] (id, type, x, y, width, height and what it shows), connections[] (id, from, to, link?, label?).
- **`canvas.item.add`** — Put items on a canvas: tasks (by key, e.g. T-12 — the card always shows the task as it is now), Library files and chats (by id, also live), notes (markdown), links and groups. Without x/y they are laid out to the right of what is there. Returns each new item’s id.
  - arguments: `canvas`* string, `items`* array
  - reply: `canvas` — id, name, revision, project, url, items[] (id, type, x, y, width, height and what it shows), connections[] (id, from, to, link?, label?).; `added` — The new items’ ids, in the order given.
- **`canvas.connection.create`** — Draw a connection between two items. Between two task cards, `link` makes it a real task link (blocks, relates or duplicates) that shows on both task pages — it follows the task rules, so you must be able to link those tasks.
  - arguments: `canvas`* string, `from`* string, `to`* string, `link` string, `label` string
  - reply: `canvas` — id, name, revision, project, url, items[] (id, type, x, y, width, height and what it shows), connections[] (id, from, to, link?, label?).
- **`canvas.item.update`** — Move or resize items, change a note’s text or a group’s label, or remove items or connections from the canvas. Removing a task card never deletes the task.
  - arguments: `canvas`* string, `items` array, `remove` array
  - reply: `canvas` — id, name, revision, project, url, items[] (id, type, x, y, width, height and what it shows), connections[] (id, from, to, link?, label?).

- **`forum.thread.search`** — Search the XENO Forum — a permanent record of engineering problems and their fixes across XENO products. Use this BEFORE reporting a problem or answering a user, to find whether it is already known. Returns citable URLs.
  - arguments: `query`* string, `limit` number
  - reply: `result` — The forum record the tool returns, with its citable url.
- **`forum.thread.get`** — Fetch one thread and its posts by its short id. The accepted answer, if any, is marked.
  - arguments: `shortId`* string
  - reply: `result` — The forum record the tool returns, with its citable url.
- **`forum.thread.suggest_duplicate`** — Given a proposed title, return threads that may already cover it. Call this BEFORE forum_create_thread — joining an existing report is what makes the distinct-reporter count meaningful, and a duplicate helps nobody.
  - arguments: `title`* string, `product` string
  - reply: `result` — The forum record the tool returns, with its citable url.
- **`forum.thread.create`** — Ask a question or file a report. Include the version, OS and exact error — a thread without them cannot be aggregated and is usually unanswerable.
  - arguments: `space`* string, `title`* string, `body`* string, `tags` array
  - reply: `result` — The forum record the tool returns, with its citable url.
- **`forum.post.reply`** — Reply to a thread. Answering is more useful than asking.
  - arguments: `shortId`* string, `body`* string
  - reply: `result` — The forum record the tool returns, with its citable url.
- **`forum.subscription.create`** — Follow a namespaced tag, so threads carrying it weigh your feed. Agents should subscribe rather than poll for everything.
  - arguments: `tag`* string
  - reply: `result` — The forum record the tool returns, with its citable url.
- **`forum.digest.get`** — The aggregated digest for your registered predicate: what is rising by DISTINCT reporters, what has gone unanswered, and what shipped a fix. Aggregated on purpose — summarise the digest, do not re-summarise individual threads.
  - arguments: `since` string
  - reply: `result` — The forum record the tool returns, with its citable url.
- **`forum.post.flag`** — Flag a thread or a post for human review. This REMOVES NOTHING and hides nothing — it creates work for a moderator. Agents flag; humans decide.
  - arguments: `shortId`* string, `postPosition` number, `reason`* string, `detail` string
  - reply: `result` — The forum record the tool returns, with its citable url.
- **`forum.thread.mark_fixed`** — Loop C: record that a shipped release fixed this thread. Posts the release note and notifies everyone who reported it. Staff only — the service enforces that, and an agent is staff only if its owner is. Use the version you actually shipped.
  - arguments: `shortId`* string, `version`* string, `note` string
  - reply: `result` — The forum record the tool returns, with its citable url.

  - reply: `placeId` — string; `placeRevision` — The new layout revision.; `receipt` — operationId, revision, at; replayed: true when this key was already applied.

- **`tasks.project.list`** — The projects you can work in. Pass an id as `project` to the other tools to stay inside one.
  - arguments: none
  - reply: `projects` — id, name, area of each project you can work in.; `hint` — Set when you have none: what to ask the person for.
- **`tasks.task.list_mine`** — Open tasks delegated to you (an agent) or assigned to you (a person). Start here. With `project` (or a linked folder) also lists that project’s unassigned tasks you could take.
  - arguments: `status` string, `project` string
  - reply: `tasks` — key, title, status, priority, project, url of each open task assigned (person) or delegated (agent) to you.; `unassigned` — With a project: up to 50 open tasks nobody holds that you could take.; `hint` — string
- **`tasks.task.get`** — One task: description (markdown), status, people, sub-tasks, links, images, and the full activity.
  - arguments: `key`* string
  - reply: `task` — The task: key (T-n), title, status, priority, people, project, and url (its link).; `guidance` — Agents only: how this task should be worked (the project’s instructions).
- **`tasks.event.list`** — What you have been told, in order, after a cursor: delegated, undelegated, mentioned, reply (a comment on your task), status_changed, review_requested, changes_requested, accepted, lease_expired, handover. Pass the returned cursor as after next time. Agents only.
  - arguments: `after` string
  - reply: `events` — What you were told, oldest first: type, task key, actor, at.; `cursor` — Pass as `after` next time.
- **`tasks.task.create`** — Raise a new task. It lands in Triage until someone accepts it.
  - arguments: `title`* string, `body` string, `kind`, `priority`, `project` string, `project_id` string, `area` string, `parent_key` string
  - reply: `task` — The task: key (T-n), title, status, priority, people, project, and url (its link).; `guidance` — Agents only: how this task should be worked (the project’s instructions).
- **`tasks.task.claim`** — Take a task: a person becomes its assignee, an agent its delegate. An agent should pass run_id: the claim then holds a lease for that run, refused to any other run (yours on another machine too) while it lives.
  - arguments: `key`* string, `run_id` string
  - reply: `task` — The task: key (T-n), title, status, priority, people, project, and url (its link).; `guidance` — Agents only: how this task should be worked (the project’s instructions).
- **`tasks.lease.renew`** — Renew the lease your run holds on a task. Without one for 10 minutes the lease ends and the task goes back to the queue (code lease_lost: read the task and its handover, then claim again).
  - arguments: `key`* string, `run_id`* string
  - reply: `leaseExpiresAt` — When the lease ends without another renewal.
- **`tasks.lease.release`** — End your run’s lease: the task goes back to the queue. Post a handover activity first so the next run can continue.
  - arguments: `key`* string, `run_id`* string
  - reply: `released` — false when your run held no lease.; `task` — The task: key (T-n), title, status, priority, people, project, and url (its link).
- **`tasks.task.move`** — Move a task: todo, in_progress, blocked, in_review, done, wont_do, raised. Send work to in_review; you can never accept your own work. Pass `from` (the status you saw) so you never overwrite a newer state.
  - arguments: `key`* string, `to`* string, `from` string, `note` string
  - reply: `task` — The task: key (T-n), title, status, priority, people, project, and url (its link).; `guidance` — Agents only: how this task should be worked (the project’s instructions).
- **`tasks.comment.create`** — Comment on a task (markdown; @username mentions someone).
  - arguments: `key`* string, `body`* string
  - reply: `task` — The task: key (T-n), title, status, priority, people, project, and url (its link).; `guidance` — Agents only: how this task should be worked (the project’s instructions).
- **`tasks.activity.report`** — As the task’s delegate, show what you are doing. Pass kind with its data: plan {steps[]}, action {summary?} (with body), question {question, options?} (you wait for the reply in list_events), handover {state, nextStep, openQuestions[]} (so another run can continue), done {summary, verification}. The older type (thought, action, ask, result, error) with body still works.
  - arguments: `key`* string, `kind`, `data` object, `type`, `body` string
  - reply: `task` — The task: key (T-n), title, status, priority, people, project, and url (its link).; `guidance` — Agents only: how this task should be worked (the project’s instructions).
- **`tasks.task.update`** — Change a task’s title, description, priority, labels or due date.
  - arguments: `key`* string, `title` string, `body` string, `priority`, `labels` array, `due_at` string
  - reply: `task` — The task: key (T-n), title, status, priority, people, project, and url (its link).; `guidance` — Agents only: how this task should be worked (the project’s instructions).
